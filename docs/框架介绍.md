## 1. 框架定位与核心能力

VLM-master 是一个**面向生产可用的视觉语言模型（VLM）微调骨架**，以 Qwen3-VL-8B-Instruct 为基座，围绕"**输入图片/视频 → 输出严格 JSON（分类 + 检测框）**"这一任务形态，打通了从数据、训练、推理到评估的完整闭环。

核心能力：

| 能力 | 说明 |
|---|---|
| 多模态输入 | 使用 Qwen 原生 image / video 输入，视频不预拼帧图 |
| 结构化输出 | 强制输出 `video_class` + `detections`（归一化 bbox）的合法 JSON |
| 四种微调模式 | LoRA、QLoRA（4-bit NF4）、DoRA、Full SFT，一套配置统一切换 |
| 多数据源 | JSONL 与 COCO 两种适配器，支持多数据集 Concat 混合训练 |
| 评估与报告 | 检测 F1 / 分类准确率 / JSON 合法率 / Mean IoU，自动生成微调前后 HTML 对比报告 |
| 训练可观测 | 独立 `metrics_log` 子系统，在线落盘指标 + 离线日志健康分析 |

## 4. 核心概念：统一消息协议

整个框架中"数据"只有一种形态——**Qwen-VL 风格的多模态对话消息（messages）**。无论是图片还是视频、COCO 还是自定义 JSONL，`Dataset.__getitem__` 返回的都是同一结构：

```python
{
  "messages": [
    {"role": "system",    "content": [{"type": "text", "text": SYSTEM_PROMPT}]},
    {"role": "user",      "content": [
        {"type": "image", "image": "/path/to/img.jpg"},   # 或 {"type":"video","video":..., "fps":2.0}
        {"type": "text",  "text": instruction}
    ]},
    {"role": "assistant", "content": [{"type": "text", "text": '{"video_class":"car","detections":[...]}'}]}
  ],
  "media": "/path/to/img.jpg",
  "media_type": "image"          # or "video"
}
```

由此带来的好处：

- **训练 / 推理共用同一套 Prompt**：`SYSTEM_PROMPT` 定义于 `datasets.py`，训练侧与推理侧（`engine.py`）都引用它，保证分布一致。
- **任意数据源可插拔**：新数据集只需产出相同 messages 协议并注册进 `build_dataset`。
- **评估直接复用**：`evaluate.py` 从 messages 中同时取 instruction（输入）和 assistant 文本（ground truth）。

**输出契约**（由 `SYSTEM_PROMPT` 约束 + `schema.py` 校验）：

```json
{
  "video_class": "类别",
  "detections": [
    {"label": "类别", "score": 0.95, "bbox": [x1, y1, x2, y2]}
  ]
}
```

`bbox` 为相对宽高的归一化坐标 `[0,1]`，`schema.Detection` 会校验长度、范围与坐标顺序。

## 5. 数据层（src/data）

### 5.1 类结构

```
VisionDataset(ABC, Dataset)        # 抽象基类，约定 __getitem__ 返回 messages
  └── JsonlVisionDataset           # 通用 JSONL 适配器（图片或视频）
        └── CocoDataset            # COCO 转 JSONL 后复用同一协议
```

### 5.2 JsonlVisionDataset

```python
JsonlVisionDataset(
    annotation_file,    # JSONL 标注文件
    media_root,         # 媒体根目录（缺省取标注所在目录）
    media_type,         # "video" | "image"
    fps,                # 视频采样帧率（图片忽略）
    validate_media,     # 启动时是否校验媒体文件存在
)
```

- 通过 `schema.load_records` 加载并用 Pydantic 逐行校验；
- `resolve_media` 将相对路径拼到 `media_root` 上；
- `validate_media()` 在 DataLoader 跑起来**之前**就发现缺失文件，尽早失败；
- `__getitem__` 产出第 4 节的 messages 协议。

### 5.3 build_dataset 工厂

```python
def build_dataset(spec: dict | list[dict]) -> VisionDataset
```

支持字典或**列表**；列表自动用 `ConcatDataset` 合并，方便混合多数据集：

```yaml
train_dataset:
  - {type: coco,  annotations: data/coco_train.jsonl, media_root: /data/train2017}
  - {type: jsonl, annotations: data/video.jsonl, media_root: /data/videos, media_type: video, fps: 1.0}
```

### 5.4 原始 JSONL 样本格式

```json
{"video":"videos/0001.mp4","instruction":"检测所有车辆...","output":{"video_class":"car","detections":[{"label":"car","score":0.95,"bbox":[0.12,0.18,0.56,0.88]}]}}
```

由 `scripts/convert_coco.py`（COCO→JSONL）与 `scripts/split_dataset.py`（按比例切分）负责生成与划分。

## 6. 模型层（src/model）

`factory.py` 中只有两种角色：私有工具函数 `_dtype` / `_load_kwargs`，以及对外的 `build_model(cfg, mode)`。

### 6.1 精度与设备自适应

```python
_dtype(cfg)          # 默认 bf16；GPU 不支持 bf16 时自动降级 fp16
_load_kwargs(cfg,..) # qlora → BitsAndBytesConfig(4bit NF4 + double quant)
                     # 否则按 device_map / distributed / full 决定是否 "auto"
```

### 6.2 build_model 四种模式

```python
SUPPORTED_FINETUNE_MODES = ("lora", "qlora", "dora", "full")
```

| 分支 | 关键动作 |
|---|---|
| **基础加载** | `AutoModelForImageTextToText.from_pretrained(...)`（可用 `image_text_to_text:false` 退回 `AutoModelForCausalLM`）；关闭 `use_cache` 以兼容 gradient checkpointing |
| **full** | 所有参数 `requires_grad=True`，直接返回完整模型 |
| **qlora** | `prepare_model_for_kbit_training` 处理 4-bit 基座 |
| **lora / qlora / dora** | 构造 `LoraConfig`（`r/alpha/dropout/target_modules/bias`，`use_dora=(mode=="dora")`），`get_peft_model` 挂 adapter；开启 `enable_input_require_grads` |

`pyproject.toml` 中未显式配置模型类，默认 `image_text_to_text=True`，适配 Qwen3-VL 的 `AutoModelForImageTextToText`。

## 7. 训练层（src/training）

### 7.1 主流程 `main()`

1. 解析 CLI：`--config / --mode / --output-dir`（后两者覆盖 YAML）；
2. 加载 YAML → `configure_logging(log_dir)`；
3. `set_seed`；
4. `AutoProcessor.from_pretrained(...)`；
5. `model = build_model(cfg, mode)`；
6. `train_set / eval_set = build_dataset(...)`；
7. 自动选择 bf16 / fp16、优化器（qlora 默认 `paged_adamw_8bit`，否则 `adamw_torch`）；
8. 构造 `TrainingArguments` 与 `Trainer`，注册 `MetricsCallback`；
9. 写入 `output_dir/training_config.json`（保证实验可复现）；
10. `trainer.train(resume_from_checkpoint=...)`（由环境变量 `RESUME_FROM_CHECKPOINT` 控制）；
11. `save_model` + `processor.save_pretrained`。

### 7.2 VisionCollator

把 `list[feature]` 打包成 batch 张量：

1. 对每条 messages 调 `apply_chat_template` 得到文本；
2. `qwen_vl_utils.process_vision_info` 抽取 images / videos；
3. `processor(text=..., images=..., videos=..., padding/truncation, max_length)` → `input_ids` 等；
4. `labels = input_ids.clone()`，padding 位置置 `-100`。

> ⚠️ **当前监督策略**：system + user + assistant 全部参与 loss，**没有**做 assistant-only 掩码。这是 README 中明确标注的未来改进点。

## 8. 推理层（src/inference）

### 8.1 VisionPredictor（engine.py）

核心思想：**模型只加载一次，评估/推理反复复用**。

```python
class VisionPredictor:
    __init__(model_path, max_new_tokens=512, device="auto")
    predict(media, instruction, media_type="video", fps=2.0) -> dict
```

`predict` 流程：

1. 构造与训练一致的 system+user messages；
2. `apply_chat_template(..., add_generation_prompt=True)`；
3. `processor` 编码文本与视觉输入 → `.to(model.device)`；
4. `torch.inference_mode()` 下 `model.generate(do_sample=False)`；
5. 截取新生成的 token → `batch_decode` → `metrics.parse_json`。

返回解析后的 JSON dict；解析失败会抛 `ValueError`，由上层（evaluate）兜底。

### 8.2 infer.py

单样本 CLI：封装一次 `VisionPredictor` 调用，把 JSON 结果写到 `--output` 或打印。

## 9. 评估层（src/evaluation）

### 9.1 metrics.py —— 指标与解析

| 函数 | 职责 |
|---|---|
| `iou(a, b)` | 归一化框的交并比，带合法性保护 |
| `match_detections(pred, target, thr=0.5)` | 按 score 降序贪心、同类别 + IoU≥阈值的**一对一匹配**，返回 `precision / recall / f1 / mean_iou` |
| `detection_f1` | 取 F1 的快捷函数 |
| `parse_json(text)` | 从模型原始输出中截取首个 `{` 到末个 `}` 之间内容反序列化为 dict |

### 9.2 evaluate.py —— 批量评估

- 用 `build_dataset` 加载验证集；
- 一个 `VisionPredictor` 遍历所有样本；
- 解析失败 → 计为非法 JSON，预测置空；
- 聚合输出：

```json
{
  "model": "...", "samples": N, "valid_json": K,
  "json_valid_rate": K/N, "iou_threshold": 0.5,
  "detection_f1": ..., "mean_iou": ...,
  "classification_accuracy": ...
}
```

可通过 `--output-json` 落盘，供 `report.py` 复用。

### 9.3 report.py —— HTML 对比报告

- 输入微调前 / 微调后两份 metrics JSON（或现场跑两次评估）；
- 生成包含样本数、Detection F1、分类准确率、JSON 合法率、Mean IoU、绝对/百分点变化、横向条形图、原始 JSON 的 HTML 报告（默认 `outputs/reports/finetune_comparison.html`）。

## 10. 公共支撑（src/common）

### 10.1 schema.py —— 数据协议

```python
class Detection(BaseModel):  label, score∈[0,1], bbox（长度4、范围[0,1]、有序）
class Annotation(BaseModel): video_class, detections
class Record(BaseModel):     video, instruction, output(Annotation|dict)
def load_records(path) -> list[Record]   # 逐行校验，非法行报具体行号
```

### 10.2 logging_utils.py

`configure_logging(log_dir)`：同时输出到控制台与 `log_dir/run.log`，统一"时间-级别-模块名"格式。

### 10.3 metrics_log/ —— 训练指标子系统

完全独立的可插拔模块（可拖进任意 HF Trainer 工程）：

| 文件 | 职责 |
|---|---|
| `callback.py` | `MetricsCallback`：训练时把每条 log 追加到 `output_dir/metrics/metrics.jsonl`，并维护 train/eval 长表 CSV |
| `parser.py`   | 离线解析已有 stdout 日志（含 tqdm 进度条内嵌 dict），还原成 DataFrame |
| `analyzer.py` | 健康规则：loss 收敛/spike、grad_norm 爆炸/消失、LR 调度形状、train/eval gap、eval_runtime 占比 |
| 产物 | `metrics.jsonl`、`train_metrics.csv`、`eval_metrics.csv`、`run_summary.json` |

## 13. 端到端数据流

以"COCO 图片检测 + LoRA 微调 + 对比报告"为例：

```
原始数据
  coco/annotations/instances_train2017.json + train2017/*.jpg
        │  convert_coco.py
        ▼
统一 JSONL            ── schema.load_records 校验 ──►  Record(video, instruction, output)
        │                                        （Pydantic 校验 bbox/label）
        │  JsonlVisionDataset.__getitem__
        ▼
messages 协议          ── system prompt + user(image+instruction) + assistant(JSON)
        │  VisionCollator
        ▼
Batch 张量            ── input_ids / attention_mask / labels / pixel_values ...
        │  build_model("lora") 挂 adapter
        ▼
HF Trainer            ── bf16 + grad ckpt + MetricsCallback 落盘 metrics/
        │
        ▼
outputs/qwen3-coco-lora/ （checkpoint-* + adapter_model.safetensors + training_config.json）
        │  VisionPredictor 加载一次
        ▼
推理 messages          ── generate(do_sample=False) ──► 文本 JSON
        │  parse_json + match_detections
        ▼
指标                   ── detection_f1 / classification_accuracy / json_valid_rate / mean_iou
        │  report.py
        ▼
outputs/reports/finetune_comparison.html（微调前后对比）
```

## 14. 微调模式对比

| 模式 | 基座加载 | 可训练参数 | 显存 | 输出 | 典型场景 |
|---|---|---|---|---|---|
| `lora`  | BF16/FP16 | 少量 adapter | 中   | adapter | 默认基线，24GB+ 单卡 |
| `qlora` | 4-bit NF4  | 少量 adapter | 最低 | adapter | 16~24GB 单卡 |
| `dora`  | BF16/FP16 | adapter      | 中高 | adapter | LoRA 基线稳定后对比 |
| `full`  | BF16/FP16 | 全部参数     | 极高 | 完整模型 | 多卡生产训练（需自行接 DeepSpeed/FSDP） |

推荐路径：**LoRA 验证流程 → 显存不足改 QLoRA → 稳定后试 DoRA → 数据/算力充足再上 Full SFT**。

## 15. 关键设计决策

1. **消息协议统一**：所有数据源最终都收敛到 Qwen-VL messages，训练 / 推理 / 评估复用同一份 system prompt，避免分布漂移。
2. **适配器而非大改**：`VisionDataset` 抽象 + `build_dataset` 工厂，新增数据源成本极低。
3. **模型工厂集中管理**：四种微调模式集中在 `factory.py`，训练器不感知模式差异。
4. **推理引擎复用**：`VisionPredictor` 只加载一次模型，解决早期"每样本重新加载 checkpoint"的性能问题。
5. **评估与训练解耦**：评估直接复用数据集协议与推理引擎，指标 JSON 与 HTML 报告可独立生成。
6. **指标子系统可拔插**：`metrics_log` 与业务无关，可整体迁移到其他 HF 项目。
7. **归一化坐标**：bbox 统一 `[0,1]` 归一化，使标签对分辨率不敏感，便于跨分辨率训练。

## 16. 已知限制与改进方向

| 现状 | 说明 / 建议 |
|---|---|
| 监督策略未做 assistant-only 掩码 | 当前 system+user+assistant 全参与 loss；生产建议只对 assistant JSON 监督 |
| 视频级检测而非逐帧 | 如需逐帧检测/跟踪，需扩展 `frame_index`、`track_id` 字段并修改输出协议 |
| Full SFT 未内置多卡方案 | 需自行接入 DeepSpeed ZeRO-3 / FSDP，并用 torchrun/Accelerate 启动 |
| 评估指标偏基线 | 生产检测还应补 mAP@50、mAP@50:95、按类别 AP、长短视频分桶 |
| QLoRA 环境要求 | 需 Linux + CUDA + bitsandbytes；CPU/Mac 不可用 |
| 数据集校验开销 | 大数据集启动校验慢，可设 `validate_media:false`，但上线前建议保持 `true` |
